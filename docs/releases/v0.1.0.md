## Migração para o novo repositório

O código-fonte foi migrado de `wilkinbarban/CRM_Sofia_Manager` (endereço que não
resolve mais) para o novo repositório público
[`wilkin-barban/CRM_Sofia_Manager`](https://github.com/wilkin-barban/CRM_Sofia_Manager).
O histórico foi preservado integralmente, sem reescrita, e o remoto `origin` do
clone local passa a apontar para o novo endereço:

```bash
git clone https://github.com/wilkin-barban/CRM_Sofia_Manager.git
```

Este é um release **source-first**: nenhuma imagem Docker genérica é publicada,
porque as variáveis `NEXT_PUBLIC_*` são embutidas em tempo de build e a imagem de
produção é construída no servidor com os valores reais.

## Stack

| Componente | Tecnologia |
| :--- | :--- |
| Framework Web | Next.js 16.4 (App Router, Server Actions) |
| Linguagem | TypeScript 5 |
| Estilização | Tailwind CSS 4 e Lucide Icons |
| Banco de dados | Supabase PostgreSQL 17 com RLS e RPCs |
| Realtime | Supabase Realtime |
| Inteligência Artificial | DeepSeek (pipeline RAG) |
| WhatsApp | Evolution API v2 |
| Pagamentos | Mercado Pago (Pix e Checkout Pro) |
| Testes | Vitest e Playwright |

## Destaques

- **Atendimento omnichannel** com a agente Sofia nos canais **Web**, **Telegram** e
  **Evolution API** (WhatsApp), com transbordo inteligente para operadores humanos
  e projeção de presença por canal.
- **Carrinho interativo** para o cliente montar o pedido com cartões visuais antes de
  enviá-lo à cozinha.
- **Console de atendimento** em tempo real, com filas IA/Humana, alertas sonoros via
  Web Audio API e indicadores de espera.
- **Estoque transacional** com RPCs atômicas no PostgreSQL, evitando sobrevenda e
  restaurando o inventário em cancelamentos.
- **Mercado Pago e Pix** com conciliação automática por webhooks idempotentes.
- **RAG com DeepSeek** sobre a base de conhecimento oficial de assados, com injeção
  dinâmica de cardápio e estoque.
- **LGPD e privacidade** por padrão: RLS, autenticação OTP, validação regional de
  telefone (DDD 41) e anonimização de logs.

## Qualidade

O release foi validado com a suíte hermética e o build de produção:

```bash
rm -rf node_modules apps/web/node_modules && npm ci
npm run lint
npx tsc --noEmit
npm run test:unit -- --allowOnly=false \
  --exclude tests/unit/roles-authentication-e2e.test.ts \
  --exclude tests/unit/web-client-operator-cart-flow.test.ts
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 \
  NEXT_PUBLIC_SUPABASE_ANON_KEY=ci-placeholder \
  npm run build --workspace @asados/web -- --webpack
```

- **Lint:** 0 erros e 6 avisos de variáveis não utilizadas (mantidos por serem
  inofensivos e fora do escopo desta release).
- **Type-check:** `tsc --noEmit` sem erros.
- **Testes:** 308 arquivos (306 herméticos + 2 suítes service-backed no CI) e 2.827
  casos na suíte hermética: 2.822 verdes, 2 ignorados e 3 timeouts de 5 s em testes
  pesados sob a carga do host de validação; os dois arquivos afetados passam 11/11 em
  isolamento (`web-only-p7-dry-run` e `payment-proof-admin-pagination`).
- **Build:** bundle de produção do workspace `@asados/web` concluído.
- **Dependências:** `npm audit` reporta **0 achados críticos e 0 altos** após a
  remediação desta release (`next` 16.4.5, `eslint-config-next` 16.4.5, `sharp`
  0.35.5, `zod` 4.6.6 e `npm audit fix` para achados transitivos). A árvore completa
  de desenvolvimento mantém 11 achados moderados em `typescript-eslint`/`minimatch`
  e `vitest`, sem superfície em runtime; `npm audit --omit=dev` (dependências de
  produção) reporta **0 vulnerabilidades**.

O workflow `.github/workflows/pull-request.yml` executa lint, type-check, build,
suíte hermética e suíte Supabase em pull requests e em pushes para `main`.

## Limitações conhecidas

- **Auditoria de dependências:** sem achados críticos ou altos desde a remediação de
  2026-11-08, e `npm audit --omit=dev` reporta **0 vulnerabilidades** nas dependências
  de produção. Restam 11 achados moderados em ferramentas de desenvolvimento
  (`typescript-eslint` e `vitest`), sem superfície em runtime; o registro completo,
  com os controles compensatórios, está em
  [`docs/security/dependency-risk-acceptance-2026-09-07.md`](https://github.com/wilkin-barban/CRM_Sofia_Manager/blob/main/docs/security/dependency-risk-acceptance-2026-09-07.md).
- **Distribuição source-first:** não há imagem Docker publicada nem binário gerado;
  o deploy é feito a partir do código-fonte com as variáveis de ambiente reais do
  ambiente de destino.
- **Duas suítes fora da execução hermética:**
  `tests/unit/roles-authentication-e2e.test.ts` e
  `tests/unit/web-client-operator-cart-flow.test.ts` dependem de um stack Supabase
  local e são executadas pelo job service-backed do CI.
